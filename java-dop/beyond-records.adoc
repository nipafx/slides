=== Records Revisited

Record benefits fall into two categories:

* internal quality-of-life +
  (fields, accessors, `toString()`, etc.)
* external contract +
  (well-defined (de)construction)

Only the latter is "needed" for DOP.

=== Carrier Types 💭

Project Amber is exploring ways to allow +
non-records to define such an external contract.

```java
// ↙ !!!              ↙ state description
interface Point(int x, int y) {

	// ...

}
```

(Strawman syntax.)

Would allow `Point` to be deconstructed, e.g. +
`point instanceof Point(int x, int y)`.

=== Carrier Types 💭

Similar for classes:

```java
// ↙ !!!          ↙ state description
class Point(int x, int y) {

	// fields
	// constructors
	// accessors
	// equals, hashCode, etc.

}
```

(Strawman syntax.)

=== Carrier Types 💭

If a connection can be made between

* state description of a class
* a matching constructor

Java can infer the same reconstruction protocol +
as for records.

⇝ That can be _very_ useful!

=== Withers 💭

Deriving new instances from existing ones:

```java
record Point(int x, int y) { }

var p0 = new Point(0, 0);
var p1 = p0 with { x = 1; };
```

(Strawman syntax.)

=== Constant Patterns 💭

Constant patterns for simpler primitive checks:

```java
record Point(int x, int y) { }

var point = // ...
switch (point) {
	// record pattern
	case Point(var x, _) when x == 0 -> // ...
	// constant pattern (probably)
	case Point(0, _) -> // ...
}
```

(Strawman syntax.)

=== Deconstruction on Assignment 💭

Unconditional deconstruction on assignment:

```java
// `Point` is a type with state description
Point nextPoint() { /* ... */ }

// if you only need `x`
Point(int x, _) = nextPoint();
```

(Strawman syntax.)
